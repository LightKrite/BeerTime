# BeerTime: понятная доска и правка списком — дизайн

Дата: 2026-08-27
Предыдущая спека: `2026-08-27-beertime-design.md` (домен и правила статусов остаются в силе)

## Задача

Первая версия работает, но доска непонятна. Клетка **показывает** вердикт на вечер (🟢🟡🔴⛔), а **редактирует** род дня (выходной / дневная / ночная / занят): тычешь одно — меняется другое, и связь между ними ниоткуда не видна. Ни легенды, ни подписей нет.

Плюс два содержательных пробела: компания заводится вручную по одному человеку, а под колонкой стоит счётчик `4/1/1`, по которому нельзя понять, кто именно свободен.

Меняем три вещи: что клетка показывает, как она редактируется, и что написано под днём. Доменные правила (`kind`, `status`, рейтинг) не трогаем — они верны.

## Клетка

Внутри клетки — **род дня** словом: `вых`, `день`, `ночь`, `занят`. Фон — **вердикт на вечер**, по прежним правилам.

Это снимает исходную путаницу: видишь то же, что редактируешь, а цвет — производная, которая пересчитывается сама.

Ручная правка помечается точкой `•` после текста. Без неё нельзя отличить «так посчитал цикл» от «я сам поставил», а это разные вещи: первое поедет вместе со сдвигом графика, второе останется.

## Правка выпадающим списком

Тык по кругу заменяется на `<select>` в каждой клетке своей строки. Пять вариантов:

```
по графику      — сбросить правку, вернуть вычисленное значение
выходной
дневная смена
ночная смена
занят
```

Выбранным показывается текущее действующее значение. Выбор отправляется сразу и перерисовывает доску целиком, поэтому имена под днями и подсветка лучших вечеров не могут разойтись с клетками.

Чужие строки остаются текстом — редактировать можно только себя, как и раньше.

Цикл `next_override()` вместе с константой `OVERRIDE_CYCLE` и своими тестами **удаляется**: после перехода на явный выбор у него не остаётся вызывающих.

## Имена под днём

Вместо счётчика `4/1/1` под каждой колонкой два списка:

```
гуляют:        Егор
               Саша
               Толя
могут, но
завтра смена:  Наташа
               Паша
```

Первый — зелёные, второй — жёлтые. Красные и «занят» не показываются: под днём отвечают на вопрос «кто может», а не «кто занят».

Пустой список отображается прочерком, чтобы колонка не схлопывалась и строки оставались выровненными.

Счётчики никуда не деваются внутри программы: рейтинг лучших вечеров по-прежнему считается по ним.

## Легенда

Под доской — расшифровка цветов, по строке на каждый, и напоминание, что править можно только свою строку.

## Данные страницы

`build_matrix()` начинает отдавать по клетке не только статус, но и род дня с признаком ручной правки, а также готовые списки имён:

```python
{
    "dates": [date, ...],
    "rows": [
        {
            "person": Person,
            "cells": [{"date": date, "kind": str, "status": str, "manual": bool}, ...],
        },
        ...
    ],
    "summaries": [(green, yellow, blocked), ...],
    "available": [{"green": ["Егор", ...], "yellow": ["Наташа", ...]}, ...],
    "best": [date, ...],
}
```

`available` считается из тех же статусов, что лежат в клетках, — как и `summaries` сейчас. Пересчитывать статусы второй раз нельзя: два источника правды разойдутся.

## Заведение компании

Шесть человек заводятся заранее, скриптом `seed.py`, чтобы каждому оставалось только выбрать себя из списка при входе.

```
Егор     2/2  2026-09-01  всегда дневные
Толя     2/2  2026-09-01  чередует
Саша     2/2  2026-09-01  всегда дневные
Федор    2/2  2026-09-03  чередует
Наташа   2/2  2026-09-03  всегда дневные
Паша     2/2  2026-09-03  чередует
```

Скрипт идемпотентен: человек с таким именем уже есть — его график обновляется, дубликат не создаётся. Это позволяет и завести компанию с нуля, и поправить чей-то цикл, не трогая проставленные людьми правки.

Якорная дата в будущем — норма: цикл разворачивается и назад от неё, ближайшие две недели заполняются корректно.

## Что сознательно не делаем

Правку диапазоном (выделить неделю отпуска разом) — отпуск проставляется по дням. Добавим, если окажется, что по дням мучительно.

## Тестирование

К существующим тестам добавляются:

- `build_matrix()` отдаёт по клетке род дня, статус и признак ручной правки; `manual` истинен ровно там, где есть запись в `override`;
- списки `available` совпадают со статусами тех же клеток, а красные и «занят» в них не попадают;
- выбор значения в списке сохраняет именно его, а `по графику` удаляет правку;
- в отрендеренной доске у своей строки клетки — `<select>` с выбранным текущим значением, у чужой — текст;
- `seed.py` заводит шестерых, повторный запуск не создаёт дубликатов и не стирает правки.
