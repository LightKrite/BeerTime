# BeerTime — дизайн

Дата: 2026-08-27

## Задача

Компания из шести друзей работает по сменному графику 2/2, часть из них чередует дневные и ночные смены. Договориться о встрече тяжело: у каждого свой цикл, и он сдвигается относительно календарной недели. BeerTime показывает на одной странице, какие ближайшие вечера подходят всем.

Ключевая идея: доступность не отмечается вручную, а вычисляется из графика смен. Человек задаёт свой цикл один раз, дальше система считает вперёд сама.

## Пользователи и доступ

Одна постоянная компания, одна ссылка навсегда. Отдельного понятия «событие» нет — страница всегда показывает ближайшие две недели.

Страница закрыта секретным путём: базовый URL вида `/b/<SECRET>/`, где `SECRET` берётся из `.env`. Это защита от случайного попадания страницы в поисковую выдачу, а не от целенаправленного взлома; для шести друзей на своём VPS этого достаточно.

Идентификация без паролей: при первом входе человек выбирает себя из списка или добавляет новое имя, `person_id` сохраняется в куке. Вернулся — сразу видит свою строку редактируемой.

## Модель данных

SQLite, две таблицы, доступ через модуль `sqlite3` из стандартной библиотеки. ORM не нужен.

```sql
CREATE TABLE person (
    id          INTEGER PRIMARY KEY,
    name        TEXT NOT NULL,
    cycle_on    INTEGER NOT NULL DEFAULT 2,   -- смен подряд
    cycle_off   INTEGER NOT NULL DEFAULT 2,   -- выходных подряд
    anchor_date TEXT NOT NULL,                -- ISO-дата первой смены цикла
    mode        TEXT NOT NULL                 -- 'day' | 'night' | 'alternate'
);

CREATE TABLE override (
    person_id INTEGER NOT NULL REFERENCES person(id),
    date      TEXT NOT NULL,                  -- ISO-дата
    kind      TEXT NOT NULL,                  -- 'off' | 'day' | 'night' | 'busy'
    PRIMARY KEY (person_id, date)
);
```

Таблицы группы нет: компания одна, вся база — это она.

`override` перекрывает вычисленный паттерн для конкретного дня. Это подмены, отпуск, больничный, а также `busy` — «не работа, но вечер занят».

## Логика

Ядро приложения — две функции. Всё остальное вокруг них.

```python
def kind(person, d):
    """Что у человека в день d: 'off' | 'day' | 'night' | 'busy'."""
    if (o := override_for(person, d)) is not None:
        return o
    n = (d - person.anchor_date).days
    period = person.cycle_on + person.cycle_off
    if n % period >= person.cycle_on:
        return 'off'
    if person.mode != 'alternate':
        return person.mode
    return 'day' if (n // period) % 2 == 0 else 'night'


def status(person, d):
    """Можно ли пить вечером дня d: BUSY | RED | YELLOW | GREEN."""
    if kind(person, d) == 'busy':
        return BUSY            # ⛔ вечер занят своими делами
    if kind(person, d) == 'night':
        return RED             # 🔴 вечером уходит на смену
    if kind(person, d + 1) == 'day':
        return YELLOW          # 🟡 может, но завтра рано вставать
    return GREEN               # 🟢 гуляем
```

Обоснование правил:

- ночная смена начинается вечером, поэтому этот вечер занят полностью;
- дневная смена завтра означает ранний подъём — можно, но осторожно;
- ночная смена завтра ранним подъёмом не грозит, спать можно днём, поэтому вечер зелёный;
- `busy` относится только к своему дню и на завтрашний расчёт не влияет: это не работа, ранний подъём из него не следует.

Отрицательные `n` (дата раньше якоря) корректно обрабатываются: используется остаток от деления с приведением к неотрицательному, чтобы паттерн разворачивался и назад.

## Экраны

### Главная — матрица

Строка на человека, колонка на дату, четырнадцать дней вперёд.

```
              Ср27 Чт28 Пт29 Сб30 Вс31 Пн01 Вт02 ...
Егор           🟢   🟢   🟡   🔴   🔴   🟢   🟢
Макс           🟡   🔴   🔴   🟢   🟢   🟢   ⛔
Ден            🟢   🟢   🟢   🟡   🔴   🔴   🟢
──────────────────────────────────────────────
итог          4/1/1 4/1/1 3/0/3 3/1/2 3/1/2 3/1/2 4/0/2
```

Заголовок колонки — число и день недели. Нижняя строка — счётчик 🟢 / 🟡 / (🔴 + ⛔) по колонке. Лучшие вечера подсвечиваются: сортировка по нулю блокирующих (🔴 и ⛔), затем по максимуму 🟢, затем по близости даты.

Своя строка редактируется прямо здесь: клик по клетке крутит правку по кругу `выходной → день → ночь → занят → сброс к паттерну`. Обновление точечное, через HTMX, без перезагрузки страницы. Чужие строки только для чтения.

На узком экране матрица прокручивается по горизонтали, колонка с именами закреплена слева.

### Настройки — `/me`

Имя, длина цикла (смен / выходных), якорная дата первой смены цикла, режим (день / ночь / чередование). Всё, что не про конкретный день; конкретные дни правятся в матрице.

## Стек и деплой

FastAPI, шаблоны Jinja2, `sqlite3` из стандартной библиотеки, HTMX для точечных обновлений. Ни сборки, ни `node_modules`.

Файлы:

```
app.py             — маршруты, доступ к базе, kind() и status()
templates/         — base.html, index.html, me.html
test_beertime.py   — тесты логики
beertime.db        — база (в .gitignore)
```

Развёртывание на собственном VPS: uvicorn под systemd, nginx впереди как reverse proxy с TLS, база лежит файлом рядом с приложением. Бэкап — копия файла базы.

Часовой пояс один на всю компанию, берётся из `.env` (`TZ=Europe/Moscow`). «Сегодня» вычисляется в этом поясе.

Переменные окружения: `SECRET` (секретный сегмент пути), `TZ`, `DB_PATH`.

## Тестирование

Один файл `test_beertime.py` на `assert`, без фикстур и фреймворков сверх pytest. Покрывает:

- арифметику цикла 2/2 — где смены, где выходные, в том числе для дат до якоря;
- чередование день/ночь по блокам для `mode='alternate'`;
- нечётные циклы (например 3/3), чтобы формула не была подогнана под 2/2;
- приоритет `override` над вычисленным паттерном;
- все правила `status`, включая зелёный вечер перед ночной сменой и то, что `busy` завтра не даёт жёлтый сегодня.

## Что сознательно не делаем

Регистрации и паролей, нескольких групп, приглашений по email, уведомлений, интеграции с календарями, мобильного приложения, истории прошлых встреч. Всё это добавляется, когда шести друзьям и одной ссылки станет мало.
